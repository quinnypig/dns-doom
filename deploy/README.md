# Persistent DNS Doom service

The deployment lives at `/home/cquinn/src/dns-doom` on `claude-superfund`, outside
the T3 scratch directory. It runs as the `cquinn` user with systemd user lingering
enabled. The web service listens only on `127.0.0.1:8770`. The named Cloudflare Tunnel `dnsdoom` supplies HTTPS at
`https://doom.shitposting.cloud`. The default view is public and read-only; a separate interactive key is enabled.
the private entry link is stored in `~/.config/dnsdoom/access-url` (mode 0600).

## Operations

```sh
systemctl --user status dnsdoom.service dnsdoom-tunnel.service
journalctl --user -u dnsdoom.service -u dnsdoom-tunnel.service -n 100
systemctl --user restart dnsdoom.service
systemctl --user restart dnsdoom-tunnel.service
```

`~/.config/dnsdoom/service.env` contains the private browser access key, immutable
Docker image ID, and deployment label. `~/.config/dnsdoom/tunnel.token` contains
the connector credential. Keep both files mode 0600 and out of Git. The installed
cloudflared binary is `~/.local/lib/dnsdoom/cloudflared` (2026.9.3). Unit templates
are in this directory; installed units are in `~/.config/systemd/user/`.

Each computation runs in a Docker container with no network outside its private
loopback, a 6 GiB memory limit, two CPUs, 256 PIDs, and 4 GiB shared memory. DNS
runs inside that container. The web application permits one active computation.
Stopping a job finishes cleanup before accepting another. Service startup and
shutdown remove only containers carrying this deployment's label.

Run metadata is atomically written to `artifacts/live/<id>/job.json`. Completed
results survive restarts. An interrupted computation is marked failed and can be
started again; the service does not claim to resume it. The latest 50 managed
runs are retained. Historical validation artifacts without job metadata are
preserved separately. systemd restarts failed services after five seconds and
starts them at boot; no interactive shell or T3 session is required.

## Update and rollback

Edit the permanent checkout and run tests. Rebuild the runtime image with
`docker build -f Dockerfile.rv32 -t dns32:local .`; compile the native extension
inside that image with `./build-native.sh` and the checkout mounted at `/work`.
Do not run a second web server on port 8770. Capture
the new `docker image inspect dns32:local --format '{{.Id}}'` value into
`DNSDEMO_IMAGE` in the environment file, then restart `dnsdoom.service` when no
computation is active. To roll back, restore the previous source/native extension
and image ID, then restart. Keep the checkpoint ELF and its expected state
matched; `./run-rv32.sh fast` regenerates both.

Back up the permanent checkout (including checkpoint and evidence), the systemd
units, and the private configuration directory. The deployment remains dependent
on this single host and its disk; it is persistent, not highly available.

To remove the deployment, disable and stop both units, then remove its named
tunnel and hostname record from the owning Cloudflare account. The original
scratch checkout remains available as migration evidence.

## GitHub Actions CI/CD

Repository: https://github.com/quinnypig/dns-doom (private).
The publishing checkout is `/home/cquinn/src/dns-doom-repository`; the original
scratch history remains local because it contains oversized generated logs.
PureDOOM is vendored with its upstream license and shareware WAD.
Selected validation reports and screenshots are committed; new runtime artifacts
are ignored and generated by the build.

`.github/workflows/ci.yml` validates pull requests and pushes to `main` on
GitHub-hosted Ubuntu runners. It builds both images, runs unit/differential and
live BIND/Knot checks, and computes a complete Doom tick, requiring pixels,
registers, PC, and game state to match the reference. Evidence is retained as a
workflow artifact for 14 days.

After successful validation, pushes to `main` (or manual runs on `main`) deploy
on the repository-scoped runner labeled `dnsdoom-production`. Pull requests never
run the deployment job. The runner is a persistent systemd user service,
`dnsdoom-actions.service`, installed at `~/.local/share/dnsdoom-runner`. The
runner user can operate Docker and the production service; repository writers
therefore control deployment on this host. No Cloudflare or browser credentials
are stored in GitHub. Existing tunnel routing needs no changes for code releases.

`deploy/release.py` prepares a new release under `~/src/dns-doom-releases`, builds
commit-tagged images and a matching checkpoint/native extension, and smoke-tests
Fibonacci before promotion. It waits up to 30 minutes for an active computation,
briefly stops the web service, and switches `~/src/dns-doom` to the release via a
symlink. Historical live runs reside in `~/.local/share/dnsdoom/live`. Local and
public HTTPS health checks gate success; a failed promotion restores the previous
release and image. Builds fail before promotion without touching the running app.

The latest release record is `~/.config/dnsdoom/deployment.json`. Previous releases
and images are retained for rollback and require periodic disk housekeeping.
To roll back, re-run a known-good revision through CI or restore the previous
symlink and image from the release record while the web service is stopped.
Do not run the old manual in-place update procedure against a release directory.

```sh
systemctl --user status dnsdoom-actions.service
journalctl --user -u dnsdoom-actions.service -n 100
gh run list --repo quinnypig/dns-doom
gh workflow run ci.yml --repo quinnypig/dns-doom --ref main
```

## Public viewing and interactive access

Share https://doom.shitposting.cloud/ with no key. Anonymous visitors can view
the current image, progress, report, and result JSON. Run/Stop requests require
the interactive cookie. The control toolbar appears only with valid interactive
access. Missing or invalid keys grant no control; old access links redirect to
the public homepage and clear the access cookie without an error.

The interactive key was rotated on 2026-10-03. The current private entry URL is
stored only in `~/.config/dnsdoom/access-url`. To rotate again, replace
`DNSDEMO_ACCESS_TOKEN` in the private environment file and restart the web service;
existing cookies become read-only. Update the private URL file at the same time.
